# API сайта и админка «Интеграции»

Сайт статичный (Vercel), поэтому всё, что связано с CRM, живёт в отдельном API — Cloudflare Worker (бесплатный тариф).
Сайт от конкретной CRM не зависит: куда уходят заявки, задаётся в админке `/admin`.

```
сайт (форма записи) ──POST /lead──▶ Worker ──▶ Битрикс24 (crm.lead.add: стадия «Новый лид», теги «Сайт» + тип)
                                         └──▶ Своя CRM клиники (POST JSON + Bearer)
                                         └──▶ Письмо на e-mail клиники (если CRM не ответила или «на каждую заявку»)
                                         └──▶ WhatsApp администратора (Cloud API, на каждую заявку, мгновенно)
                                         └──▶ Журнал заявок (KV) + админка
сайт (виджет слотов) ──GET /slots──▶ Worker ──▶ CRM (этап 2)
```

## Развёртывание (один раз, ~10 минут, нужен аккаунт Cloudflare — бесплатный)

```bash
cd worker
npx wrangler login                          # откроется браузер — войти в Cloudflare
npx wrangler kv namespace create SETTINGS   # вернёт id → вставить в wrangler.toml
npx wrangler secret put ADMIN_PASSWORD      # пароль админки
npx wrangler deploy                         # адрес вида https://interna-api.<account>.workers.dev
```

Потом в Vercel → проект → Settings → Environment Variables добавить `PUBLIC_API_URL=https://interna-api.<account>.workers.dev` и сделать Redeploy — сайт начнёт слать заявки туда.
Для писем (запасной канал) по желанию: `npx wrangler secret put RESEND_API_KEY` (resend.com, домен клиники подтверждается там же) — без ключа письма идут через formsubmit.co, адрес нужно один раз подтвердить по письму-активации.
На своём домене: в Cloudflare привязать `api.internaclinic.kz` к воркеру.

## Админка `/admin`

Логин — любой, пароль — `ADMIN_PASSWORD`. Разделы:

- **Куда отправлять заявки**: никуда / Битрикс24 / своя CRM / обе.
- **Битрикс24**: входящий вебхук, ответственный, источник, стадия лида (`STATUS_ID`, по умолчанию `NEW` — «Новый лид») и поле тегов (строковое `UF_CRM_…`, создаётся в CRM один раз). Кнопка «Тестовая заявка» создаёт лид и показывает ответ Битрикса.
- **Своя CRM**: адрес приёма и токен. Формат тела запроса описан в форме.
- **Уведомления**: e-mail клиники и режим — «только если CRM не ответила» или «на каждую заявку».
- **Заявки в WhatsApp администратора**: Phone number ID, номера получателей, имя и язык шаблона. Токен — секрет `WA_TOKEN`. Настройка ниже.
- **Журнал**: последние заявки с типом и результатом доставки — видно, если CRM не ответила.

## Заявки в WhatsApp администратора (Meta WhatsApp Cloud API)

Почта для клиники медленная, поэтому каждая заявка сразу уходит сообщением в WhatsApp администратора — через официальный
Cloud API Meta, без сторонних шлюзов. Нужен бизнес-аккаунт Meta и отдельный номер под API (его нельзя использовать в обычном
приложении WhatsApp; можно взять новый). Получатели — обычные номера администраторов, им ничего ставить не нужно.

Настройка (делает клиника или мы с доступом к её Meta Business Suite, ~1 час без учёта проверки бизнеса):

1. business.facebook.com → создать бизнес-портфолио клиники (если нет) и пройти **верификацию бизнеса** (документы компании, от 1 дня до 2 недель).
   Без верификации API работает в тестовом режиме: до 5 получателей, которых нужно вручную добавить в список.
2. developers.facebook.com → **Create App** → тип Business → добавить продукт **WhatsApp**. В разделе WhatsApp → API Setup привязать номер клиники
   (придёт код подтверждения по SMS или звонком) и скопировать **Phone number ID**.
3. Постоянный токен: Business Settings → Users → **System users** → добавить системного пользователя (Admin) → Generate token →
   выбрать приложение, права `whatsapp_business_messaging` и `whatsapp_business_management`, срок — never expire. Токен → `npx wrangler secret put WA_TOKEN`.
4. Шаблон: WhatsApp Manager → Message templates → Create → категория **Utility**, имя `lead_site`, язык Русский (`ru`), тело:

   ```
   Новая заявка с сайта · {{1}}
   Имя: {{2}}
   Телефон: {{3}}
   {{4}}
   ```

   Примеры для модерации: `Приём`, `Айгерим`, `+77001234567`, `Услуга: Колоноскопия · Дата: 12.11.2026 · Связь: WhatsApp · Страница: /service/colonoscopy`.
   Утверждение занимает от минут до суток.
5. В админке `/admin`: Phone number ID, номера получателей через запятую (в формате `7700…`, без плюса можно), имя шаблона `lead_site`, язык `ru` → «Сохранить» → «Отправить тестовую заявку».
   В ответе строка `whatsapp ✓` — сообщение пришло.

Цена: шаблонные сообщения категории Utility Meta тарифицирует поштучно по ставке для Казахстана (актуальная цена — в кабинете Meta, раздел
WhatsApp → Billing); при 300–500 заявках в месяц это единицы долларов. Если получатель сам написал на номер клиники, ближайшие 24 часа
сообщения ему бесплатны и можно обходиться без шаблона (поле «Имя шаблона» пустое) — для постоянной работы это ненадёжно, нужен шаблон.

Ограничения Meta: в параметрах шаблона нельзя переносы строк, поэтому детали заявки склеены через « · »; файл резюме в WhatsApp не передаётся
(только имя файла в деталях, сам файл — во вложении письма через Resend). Если CRM не ответила, в начале сообщения появляется пометка «⚠️ CRM не ответила».

## Что получает Битрикс24

Каждая заявка типизируется (по полю `type` с сайта или по услуге/странице): **Приём**, **Check-up**, **KIDS**, **Вакансия**, **Акция**.
Лид: `TITLE` = `Сайт · <тип> · <услуга> · <телефон>`, `STATUS_ID` = стадия из настроек, `SOURCE_ID` = `WEB`, в поле тегов — `Сайт, <тип>`,
в `COMMENTS` — тип, теги, услуга, дата, время, способ связи, страница, UTM. Когда клиника даст доступ к порталу: создать входящий вебхук с правом `crm`,
посмотреть код стадии «Новый лид» и код поля тегов, вписать их в админку и нажать «Тестовая заявка».

## Контракт для своей CRM

`POST {url}` с заголовком `Authorization: Bearer <token>` и телом:

```json
{ "source": "internaclinic.kz", "name": "Имя", "phone": "+7705…", "service": "Колоноскопия", "type": "visit",
  "date": "12.11.2026", "time": "Утро · 08:00–12:00", "contact": "WhatsApp",
  "slot": "12.11.2026, Утро · 08:00–12:00", "format": "", "page": "/service/colonoscopy",
  "utm_source": "", "utm_medium": "", "utm_campaign": "" }
```

Ответ — любой 2xx. Для слотов записи (этап 2) CRM должна отдавать `GET /slots?doctor=&date=` → `[{ time, iso, doctorId }]`.

## Вход в админку сайта (`/admin/` на сайте)

OAuth для админки контента переехал на Vercel: `api/auth.js` и `api/callback.js`, настройка — в корневом README (раздел «Админка: настройка входа»). Маршруты `/auth` и `/callback` в воркере больше не нужны.

## Повторная отправка в CRM (очередь)

Если Битрикс24 или своя CRM не ответили, заявка не теряется: копия сразу уходит письмом, а сама заявка
попадает в очередь `pending` в KV. Cron (`[triggers] crons = ["*/15 * * * *"]` в wrangler.toml) повторяет
отправку до 6 раз с нарастающей паузой: 15 мин → 30 мин → 1 ч → 3 ч → 12 ч → 24 ч. Результат повтора
виден в журнале заявок (`retried: N`), после 6 неудач — пометка `retry: error`.

- `GET /health` показывает число заявок в очереди (`pending`).
- `POST /retry` с паролем админки запускает повтор вручную, не дожидаясь cron.

## Отклики на вакансии

Форма на /vacancies шлёт заявку `type: vacancy` с полями `position`, `message` и, при желании, `resume`
(файл PDF/DOCX до 5 МБ в base64). В Битрикс24 файл не передаётся (уходит имя файла в комментарий),
во вложение письма он попадает только через Resend (`RESEND_API_KEY`); formsubmit вложения не принимает.
